# Разметчик диалогов

Одна страница `index.html`, без сервера. Работает на GitHub Pages.

## Для разметчика
1. Открыть страницу, выбрать запись в списке «Записи», ввести пароль (его присылает владелец), «Открыть запись».
2. Слушать, править текст, спикера, границы. Числа писать словами, без скобок.
3. «Скачать проверенную разметку .json» и прислать файл владельцу. Разметка также автосохраняется в браузере.

Можно открыть и свой файл: «Открыть аудио» (+ черновик .json), тогда ничего не загружается в сеть.

## Для владельца: добавить записи
Аудио лежит в репозитории только в зашифрованном виде (AES-256-GCM, ключ из пароля, расшифровка в браузере).

```bash
LABELER_PASSWORD='длинная парольная фраза' node tools/publish.mjs ПАПКА_С_АУДИО
git add data && git commit -m "add recordings" && git push
```

В папке: `r001.wav` (+ необязательно `r001.json` — черновик разметки). Скрипт создаёт `data/*.enc` и `data/index.json`. Исходные wav/json в репозиторий не коммитить. Пароль передавать разметчикам отдельно, не через репозиторий.


### Без шифрования
Если все говорящие согласились на публикацию: `PLAIN=1 node tools/publish.mjs ПАПКА_С_АУДИО`. Файлы кладутся в `data/` как есть, пароль на странице не нужен.

## Обновлённые черновики

Редактор состоит из `index.html` и `labeler-core.js`; оба файла нужны на хостинге.
Для r001 по умолчанию загружается последняя пользовательская версия: 44 реплики.
Исходные и новые модельные черновики сохранены отдельно. r002–r004 используют
новые кандидаты с локальными large-v3 / podlodka и диаризацией.

Автосохранение привязано к SHA-256 аудио. Уже сохранённые в вашем браузере правки
сохраняют приоритет. Чтобы явно загрузить обновление сайта, откройте аудио и
нажмите «Загрузить опубликованный черновик»; редактор спросит перед заменой.

Для каждой реплики есть отметка проверки по аудио. Изменение текста, говорящего
или времени сбрасывает её. Незавершённую работу можно скачать как черновик.
Проверенный экспорт содержит только transcript и четыре поля реплик; перед
ним нужно определить все голоса, написать числа словами и проверить реплики.
Автоматические кандидаты не объявлены ручными эталонами.

В панели спорных мест доступны расхождения двух ASR с переходом к времени записи.
Проверить редактор: `node --test tests/*.test.cjs`.

В очередь спорных мест добавлено третье мнение: GigaAM v3 (локально, sherpa-onnx). У существующих пунктов
показано, к чьему варианту ближе GigaAM; отдельно добавлены места, где GigaAM не согласна с large-v3.
Это подсказки, а не доказанные ошибки; эталон по-прежнему требует прослушивания человеком.
